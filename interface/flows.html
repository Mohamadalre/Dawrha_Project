١ · دورة الطلب الكاملة: من إنشاء المستخدم حتى التسليم للمستودع

الفلو الأهم في النظام — يجمع الأطراف الأربعة (مستخدم / محرك التوزيع / سائق / مستودع) مع مزامنة Odoo في كل مرحلة.
1️⃣ المستخدم ينشئ طلب جمع (فوري أو مجدول)
يختار المنتجات والكميات والعنوان — تُحسب القيمة التقديرية من الأسعار والكميات
POST /api/v1/collection-requestsQUEUED
📱 شاشة إنشاء الطلب
↓
2️⃣ محرك التوزيع يفحص «من يستطيع خدمة هذا الطلب الآن؟»
5 شروط إلزامية: حساب ACTIVE · شاحنة مُسندة وغير معطلة · وردية نشطة تغطي الوقت الحالي · السائق غير منشغل · السعة المتبقية ≥ الوزن التقديري
dispatch-candidates.service — findEligible()
سائقون مؤهلون ✔
يُفتح عرض Offer للسائق الأعلى ترتيبًا بنافذة قبول (300 ثانية افتراضيًا)
socket /collection → request:assignedOFFERED
📱 شاشة الجولة — بطاقة العرض
لا يوجد مؤهل ✖
لا أحد يستوفي الشروط → الطلب ينتظر تدخل الأدمن (إسناد يدوي أو انتظار)
socket → request:needs_adminNEEDS_ADMIN
📱 شاشة طلبات الجمع (الأدمن)
↓
3️⃣ قبول العرض = إسناد وبناء الجولة
يُسند الطلب للسائق، تُنشأ الرحلة (ROUTE) وتُرتب المحطات، ويُبلَّغ المستخدم بوصول سائق له
ASSIGNEDPLANNED
📱 الجولة بعد الإسناد — قائمة المحطات 📱 طلباتي — شريط التقدم لحظيًا
↓
4️⃣ السائق يتوجه إلى المحطة ويُعلن وصوله
الضغط على «وصلت» يوثّق أوقات الانطلاق والوصول ويبثّ الحالة الجديدة للمستخدم
PATCH /api/v1/driver/collection-requests/:id/arrivedEN_ROUTE → ARRIVED
📱 زر «وصلت»
↓
5️⃣ وزن الكميات على الميزان وتسجيل الوزن الفعلي
يُثبَّت الوزن الفعلي — أساس الدفع النهائي — ويُدفع Job REGISTER_INTAKE إلى Odoo لتسجيل الوارد (idempotent)
PATCH .../collected { actualWeightKg }PICKING
📱 حقل الوزن + زر «سجّل الوزن»
↓
6️⃣ تسليم الكمية للمستودع
تسليم إما لمستودع محدد (warehouse_id) أو لمقر الانطلاق — تُسجَّل لحظة التسليم ويُحرَّر السائق
PATCH .../delivered { warehouse_id? }DELIVERED
📱 زر «سُلّمت»
↓
7️⃣ اكتمال الجولة وإغلاق الطلب
عند إغلاق آخر محطة تُكتمل الرحلة ثم الطلب، يُكافأ المستخدم بالنقاط، ويُشعر الطرفان، وتُحدَّث مخزونات Odoo
COMPLETEDPointsWallet · registerIntake

٢ · خطة المؤسسة (ORG_PLAN) — تخطيط الجمع لمؤسسة

المؤسسة تخطّط عدة طلبات دفعة واحدة في خطة واحدة — محرك التوزيع يلتقط كل سطر ويولّد منه طلبًا يسلك دورة الفلو ١ كاملة.
1️⃣ المؤسسة تُنشئ الخطة
خطة جمع (مثلاً: جمع أسبوعي من 5 فروع) مع أسطر كل منها: منتج، كمية، عنوان، موعد
POST /api/v1/collection-plansDRAFT
↓
2️⃣ النظام يولد طلبًا لكل سطر
كل سطر → طلب من نوع ORG_PLAN بموعد مجدول — تُحسب القيم التقديرية من الأسعار
SCHEDULED → QUEUED
📱 نوع الطلب «خطة مؤسسة ORG_PLAN»
↓
3️⃣ نفس محرك التوزيع تمامًا
مع موعد مجدول: يُعرض الطلب قبل الموعد على السائقين المؤهلين — لا فرق في آليات الفرز والعرض والإسناد
↓
4️⃣ … ثم تسلك كل دورة الفلو ١
قبول → وصول → وزن → تسليم → COMPLETED
← ارجع إلى الفلو ١
📱 الطلبات المولّدة تظهر عند الأدمن (نوع ORG_PLAN)
لماذا تُفصل الخطة عن الطلبات؟ الخطة كيان تخطيطي (تتبع المطالبات والتعديلات والإلغاء) أما الطلبات فهي الوحدات التشغيلية التي يتعامل معها محرك التوزيع والسائق. تعديل خطة نشطة يعيد تقييم طلباتها.

٣ · انضمام سائق جديد: Onboarding + اعتماد Odoo

السائق يبني ملفه عبر التطبيق، ثم يُنشأ في Odoo، والأدمن لا يستطيع الموافقة عليه مباشرة — القرار يأتي من Odoo عبر Webhook.
1️⃣ تسجيل + تحقق OTP
تسجيل الدخول برقم هاتف وبريد — الحساب يولد INACTIVE ثم يُفعَّل عبر رمز التحقق
POST /api/v1/auth/register/collectorINACTIVE → PENDING_PROFILE
📱 دخول السائق 📱 شاشة التحقق OTP (نفس النموذج)
↓
2️⃣ المعلومات الشخصية + موقع العمل
الاسم والهاتف ثم اختيار المحافظة والعنوان النصي (المعرّف الفعلي للمحافظة يصل من قائمة المحافظات)
POST /api/v1/onboarding/collector/information
POST /api/v1/onboarding/collector/location { address, provinceId }
📱 خطوتا المعلومات والموقع
↓
3️⃣ رفع الوثائق (multipart)
وجه الهوية الأمامي والخلفي + رخصة القيادة — تُرفع لـ Cloudinary وتُسجَّل بحالة PENDING
POST /api/v1/onboarding/collector/upload-doc { fileType }PENDING
📱 خطوة الوثائق
↓
4️⃣ إنشاء السائق في Odoo (PUSH_DRIVER_REQUEST)
Job يُنشئ السائق في Odoo مع وثائقه — من هذه اللحظة يدير Odoo دورة حياته
odo-sync → recycle.driver.*
↓
5️⃣ قرار Odoo عبر Webhook
موافقة = ACTIVE مع شاحنة ووردية ومستودع · رفض = REJECTED · طلب تعديل = NEED_CHANGES + إعادة رفع مستندات مرفوضة فقط
POST /api/v1/odoo/webhooks/driver-decision { backend_driver_id, approved, truck_odoo_id, shift_odoo_id }
موافقة ✔
ACTIVE + إنشاء إسناد الشاحنة (assignment) + تعيين الوردية → السائق يبدأ العمل
ACTIVE
📱 الرئيسية — الشاحنة والوردية 📱 الحسابات لدى الأدمن (السائقون في Odoo)
طلب تعديل ✎
المستندات المرفوضة فقط تُعاد عبر إعادة الرفع — لا يبدأ من الصفر
NEED_CHANGESPATCH /api/v1/media/:id/reupload
📱 ملفي — قسم الوثائق
مهم: محاولة الأدمن تغيير حالة سائق تُرفض بـ 400 DRIVER_MANAGED_IN_ODOO — كل القرارات (قبول/رفض/حظر/نقل مستودع) قادمة من Odoo حصرًا، وكلها تصل عبر نفس الـ webhook مع إشارات (warehouse_change_only · documents_only · approved_media_ids…).

٤ · إدارة السائق يوميًا: استلام الشاحنة، تغيير الوردية، المشاكل

استلام الشاحنة بداية الوردية 🛻
سحب يدوي: يفتح تسليمًا (handover) ويبدأ جلسة التتبع — دون تسليم مفتوح لا يُسمح بالبث أو الاستلام

↓
طلب تغيير الوردية 🔁
يختار الوردية الجديدة → الطلب يذهب إلى Odoo → القرار يعود عبر webhook
POST /api/v1/shift-change-requests { truckId, shiftId }PROCESSING

↓
قرار Odoo
قبول = وردية وشاحنة جديدتان · رفض = يبقى كما هو مع سبب الرفض

↓

٥ · الإسناد اليدوي من الأدمن (NEEDS_ADMIN)

الطريق الاحتياطي عندما لا يجد محرك التوزيع سائقًا مؤهلًا، أو عندما يريد الأدمن حسم طلب معلّق فورًا.
1️⃣ الأدمن يرى الطلبات المعلّقة
تنبيه فوري عبر socket (request:needs_admin) + فلتر الحالة في الجدول
📱 لوحة التحكم — بطاقة «بحاجة إسناد» 📱 جدول الطلبات — صف NEEDS_ADMIN
↓
2️⃣ اختيار السائق المطلوب
نموذج الإسناد اليدوي — المعرّف المطلوب هو collector_profiles.id (وليس معرّف الحساب)
POST /api/v1/admin/collection-requests/:id/assign { driver_id }
مؤهل ✔
الحجز المباشر على الطريق دون مرحلة عرض — السائق يراه محطة في جولته
ASSIGNED
📱 يظهر فورًا في جولة السائق
غير مؤهل ✖
يعاد الرفض بالكود 409 — محرك الأهلية نفسه يتحقق حتى في الإسناد اليدوي
409 COLLECTION_DRIVER_NOT_ELIGIBLE

٦ · التتبع المباشر للشاحنات (Socket.IO)

السائق يبث موقعه 🛻
شرط مسبق: تسليم مفتوح (استلم الشاحنة) — البث يُكتب في Redis (TTL محدود) مع سجل تاريخي
socket /tracking → truck:location { truckId, lat, lng, speed }
📱 الرئيسية — زر «بدء البث»
↓
النظام يخزن ويوّجه
تحديث آخر موقع + سجل + قائمة الشاحنات النشطة في Redis، وإعادة بث فورية لغرفة الأدمن
↓
الأدمن يتابع على الخريطة
الاشتراك بكل الشاحنات (admin:subscribeAll) أو شاحنة محددة — وتصل أحداث التوقف والانقطاع تلقائيًا
socket /tracking → truck:location · truck:stopped · truck:session
📱 الأسطول — خريطة التتبع المباشر
↓
انقطاع السائق ⚡
تثبيت آخر موقع مع DRIVER_DISCONNECT وبث truck:stopped — لا يضيع الأثر ولا يُترك بلا حالة
